# earlyErrorQueue

`earlyErrorQueue` 用于处理监控 SDK 初始化前发生的早期错误。它配合一段可直接复制到 HTML head 的 inline bootstrap 使用：bootstrap 先捕获 `error`、资源加载失败、`unhandledrejection` 和 Reporting API 报告；完整 SDK 初始化后再接管队列、补齐上下文并统一发送。

## 队列去重和限制

队列是有界 ring buffer，会限制条数、估算字节数和存活时间。同一错误重复出现时会合并 `count`，URL 会在进入队列前过滤常见敏感 query。

<CodeOrSourceMdx language="typescript">{queueDemo}</CodeOrSourceMdx>

## inline bootstrap

`script.tsx` 不是 import 入口，它是 copy-only 片段。实际落地时将文件中的 IIFE 复制到业务首个 script 之前，越早执行越能覆盖首屏白屏前的错误。

<CodeOrSourceMdx language="typescript">{scriptSource}</CodeOrSourceMdx>

Storybook 中为了避免直接安装全局监听，使用模拟队列演示 bootstrap 暴露的 `window.__EARLY_ERROR_QUEUE__` 结构。

<CodeOrSourceMdx language="typescript">{bootstrapDemo}</CodeOrSourceMdx>

## 接管并 flush

SDK 初始化完成后创建 `EarlyErrorQueue`，调用 `captureGlobal()` 读取并停止全局 bootstrap 监听，再通过 `flush()` 补齐 `appId`、`release`、`route`、`userId` 等上下文。

<CodeOrSourceMdx language="typescript">{flushDemo}</CodeOrSourceMdx>

## 具体实现原理

1. **文件职责**：`script.tsx` 提供 copy-only inline bootstrap；`index.ts` 提供可 import 的 SDK 接管类，并用 class 私有字段负责有界队列、去重和统计；`browser/**` 负责读取浏览器事件、全局队列和运行时上下文；`transport/sendEarlyErrorPayload.ts` 负责 fetch/beacon 发送；`core/**` 只保留清洗、去重 key、未知错误标准化这类纯逻辑 helper。
2. **核心流程**：HTML head 先执行 bootstrap，错误进入全局队列；SDK 初始化后 `captureGlobal()` 取走事件；`flush()` 调用 `enrichEarlyErrors()` 补业务上下文后发送。
3. **关键技术点**：资源错误必须通过捕获阶段监听；队列满时丢弃最旧事件；入队前做 URL 敏感参数过滤；页面隐藏时可选 `sendBeacon`，失败后降级 `fetch keepalive`。
4. **数据流向**：浏览器事件 → bootstrap 全局队列 → `EarlyErrorQueue` 内存队列 → enriched payload → 后端监控接口。
